# Безопасность

## Правило

Токены и пароли не хранятся в этом репозитории. Секрет живёт только в момент
запроса к GitHub API и не попадает ни в файлы, ни в историю коммитов, ни в
вывод программы.

## Как код обращается с токеном

- Токен читается из переменной окружения `GITHUB_TOKEN` или `GH_TOKEN`
  (`cmd/statsgen/commands.go`) и передаётся в клиент конструктором.
- Клиент (`internal/githubapi`) кладёт его только в заголовок
  `Authorization: Bearer` и никогда не пишет в лог.
- Тексты ошибок API проходят через `redact`: значение токена заменяется на
  маску, поэтому токен не может утечь через сообщение об ошибке.
- Ни один токен не передаётся аргументом командной строки: в `ps` его видно,
  а значит он попадёт в историю оболочки.

## Откуда брать токен

Вводить вручную и не сохранять:

```
./scripts/refresh.sh
```

Либо взять из связки ключей системы, не выводя его в терминал:

```
TOKEN=$(printf 'protocol=https\nhost=github.com\n\n' | git credential fill | sed -n 's/^password=//p')
GITHUB_TOKEN="$TOKEN" go run ./cmd/statsgen stats --user ViktorVanyuta --out assets
unset TOKEN
```

Токен не должен попадать в `argv`, в файлы, в `.env` и в удалённые
репозитории.

## Проверка

Сканер `internal/leaks` ищет строки, похожие на токены GitHub
(`ghp_*`, `github_pat_*`, `gho_*`, `gh[su]_*`), в рабочем дереве,
в индексе и во всей истории коммитов:

```
go run ./cmd/statsgen check-leaks                # дерево + история
go run ./cmd/statsgen check-leaks --staged-only  # только индекс, быстро
```

Команда возвращает код `1`, если нашла что-то похожее на токен.
`scripts/refresh.sh` вызывает её перед коммитом и отменяет коммит при находке.

Если токен всё же попал в историю: rewrite через `git filter-repo` или
`git filter-branch`, затем `git push --force`, а токен нужно отозвать на
GitHub — старая история может остаться в клонах и в кешах сервера.
